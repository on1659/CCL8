# goal: chicken-heist-horror-night

## One-line Goal
v0.24 horror bundle: true darkness with a per-player flashlight, a twistier off-spine maze, monster-proximity sonar pings, death at HP 0, hide-in-jar as the new guaranteed escape valve, 1.35×-silhouette monsters, and aggro that essentially never releases — with the escape guarantee moved from legs (A3's 10s kinematic budget) to space (a jar within 700u of every cell, machine-checked at load).

## Background / Motivation
Developer request (2026-08-20, 8 items, verbatim intent):
① Too bright — remove **ALL** ceiling lights; only a faint glow attached to the player. ② **Flashlight**: a key toggles a light cone. Given by default now, but structure it so it becomes purchasable later ("생각잘하고 구조짜"). ③ Maze has too many straights — more corners, more confusing. ④ When monsters come **near**, show the sound-wave visual so I can tell — audio too, but the visual is wanted. ⑤ If HP hits 0 from monster attacks the player must **die** — not one-shot, but death must exist. ⑥ Hideable objects mid-map — **jars** only for now; intent: without a glove you always lose, so hide. ⑦ Monsters are too small — bigger, "small isn't scary". ⑧ Chasing monsters STILL drop aggro — make it essentially never release ("웬만해선 정말 웬만해선").

Developer rulings taken during probing (settled — do not relitigate):
- **Death** = the night ends immediately; only trucked loot scores (solo). Multi: dead player spectates; all-dead = night over. This is a recorded **narrow reversal of 즉사 금지** — recorded narrowly in the ledger below.
- **Blackout** becomes "your flashlight flickers and dies" — the blackout system, timers, and ×2 bonus all stay; only its expression changes.
- **The jar is the new escape valve**: with aggro nearly never releasing, the jar replaces the v0.22 10s budget as the guaranteed escape. Hiding while carrying loot is priced (panel-decided rule in D6).
- **Waves**: only monster-approach pings render in the lit phase, ever. All existing wave sources remain blackout-only.
- **Model plan** (user directive): this document and its design were authored by Fable; the implementing session (Opus) writes the code.

Recorded reversals this round carries: (a) 신규 시스템 1개 원칙 suspended for a v0.24 8-item bundle (v0.6/v0.15/v0.21 lineage; restored v0.25); (b) 즉사 금지 narrowly reversed — HP 0's third hit is death, one-shot death stays banned; (c) the wave contract ("파동 렌더는 정전 중에만") amended by exactly one lit-phase class; (d) the blackout's visual expression (v0.15 전면 감광 + lamp cut) superseded by flashlight-death; (e) v0.20's 넉다운-재충전 balance clause superseded by pad-only healing. The 몸축척 동결 list is **not** amended — see D7.

Design settled by a 4-perspective panel + cross-examination against the full-file recon (`horror-recon.md`: lighting inventory, procgen levers, wave system, HP/failure machinery, scale/aggro). Decisions below are panel-settled — **do not relitigate during implementation**.

## Design Decisions (panel-settled — do not relitigate during implementation)

### D1 — Lighting rebuild (render-only, v0.15 shape)
`HEMI_LIT 0.12→0.03`, `MOON_LIT 0.06→0.02`, `SKY_NIGHT_HEX 0x03060c→0x02040a` (`?bright=1` A/B keeps the old values). **All 10 cell lamps: intensity 0 forever** — light objects and LAMP_POS kept intact (D29 recompile contract; self-check :5803 on LAMP_POS[5] still passes untouched); `bulbMat` parked on the dark hex 0x241d14 permanently (the blackout role migrates to the torch death, D2). **Survives untouched**: padLight (:1444), kitchen brooder + bulb in the powered phase (:1956 — the 정전=조리정지 causal anchor, and the creepiest object in the new palette), all 4 doorFrames + stair blue (:1588-1591), doorSpill polarity (:2685), cart phosphor (:1842-1848), truck headlights + HEADLIGHT_DARK clamp, the egg emissive **inversion** (lit=dim / blackout=bright — a load-bearing blackout signal), and the entire v0.16 MeshBasic set (chicken eyes/rings/!/?/gauge). **LANTERNS repurposed** as the per-player faint glow: follow the player at intensity 0.35 / distance 90 always; blackout+held boosts to the existing egg-lantern behavior. **New**: jar-lid phosphor rims 0x6f8fb0 (honest-beacon class; lands with the jar commit). Light count 19→23 (the 4 torch SpotLights), fixed at load. `applyDark` keeps all its members; the lamp/bulb lines become structural no-ops; **the torch death is NOT in applyDark** — single-writer rule (the kitchenLight two-writer situation is the precedent not to repeat).
*Rationale*: fear = contrast, and the MeshBasic honest-beacon set emits **zero light** — in true darkness it becomes pure orientation (truck/stairs/exits answer the 3-second criterion) without illuminating anything. Repurposing LANTERNS costs zero new lights. Zero LOGIC constants move; the v0.22 frozen-11 checks (:5903-5906) ship byte-identical and are the machine proof of scope.
*Rejected*: 4 new glow PointLights (27 lights, per-vertex cost on every Lambert surface — LANTERNS already exist); removing beacons for purer darkness (kills the completion criterion and three standing contracts); keeping lamps merely dimmed (half-dark is the current build's problem, and the developer said remove **all**); full-time DARK egg emissive (deletes a blackout signal).

### D2 — Flashlight
**KeyT toggles** (F is taken by the cart — verified :5738). Client sends `{a:'torch'}` through the existing acts queue; host flips the flag; the snapshot mirrors it. **4 SpotLights pre-allocated at load** beside LANTERNS (D29): angle 0.46rad, distance 350, decay 1.5, color 0xfff0d8, intensity ~2.0, own Object3D targets, positioned per-frame from `p.x/p.z/p.yaw` at y≈46 — **never camera-parented** (third-person camMode 1 swings; remote players need world-space anyway). **One intensity writer**: the per-frame avatar loop computes `torchState==2 && p.active && !p.dead && (blackout ? dieCurve : 1)`. Blackout expression: `torchDieT=1.2s` stutter (random 40–120ms flicker + clunkS ticks) then 0 for **all** players regardless of toggle; the 30s/10s warn dips (warned30/warned10, WARN_DIP_T) retarget as torch micro-stutters — free foreshadowing. Cone rendering: Lambert kept, segBox walls subdivided (~len/60 × 2), plus one additive transparent cone mesh per player toggled with the torch (the always-legible beam). All render params **plain consts** (HEMI_LIT precedent — not T(), off the tune hash). State: `p.torch` tri-state on makePlayerState (default 2 = owned-on via `TORCH_DEFAULT`), resetWorld line, `pl[16]`, width 16→17. **Purchasable-later** = flip TORCH_DEFAULT to 0 + one E-chain branch on the SHADES template — nothing else built now. **Torch-off has ZERO stealth meaning** and no UI ever says 숨기/은신; the teaching is D-DARK3's ring threshold lowered 0.15→0.05 (matching the gauge draw threshold) — a player crouching torch-off in blackness watches the ring+gauge appear anyway: one dead assumption, zero tutorial text.
*Rationale*: every piece has a working in-file precedent (LANTERN pre-allocation, headA/headB SpotLight+target, the sunglasses flag/tuple/reset template, the acts queue, D-DARK3). The toggle earns its keep three ways despite no LOGIC meaning: the blackout needs an on-state to kill, the purchase structure needs the flag, and remote cones are teammate-position information in a dark world. Distance 350 = the cone shows the next junction, not the one after; a chicken at the cone's tip has been able to see you for 240u of your approach — **the cone is what you can afford to know, not safety**.
*Rejected*: F key (collision); camera parenting (third-person swing); `mat()`→Phong (per-fragment ×23 lights, whole-scene restyle); shadow maps (zero infrastructure, recompile hitch, perf cliff); battery/fuel (a new resource system that double-charges the blackout's authored fear); T()-wrapping cone params (render values stay off the handshake); building the shop branch now (widening the shop is a separate developer unlock).

### D3 — Corners

## New Valve Contract (v2 — replaces A3, keeps everything else)

All non-chase checks untouched.
